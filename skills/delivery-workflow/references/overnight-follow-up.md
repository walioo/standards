# 定时确认与夜间持续跟进

将白天未完成、已有明确目标的需求、功能、缺陷和测试接续到夜间，次日交接可验证结果。复用现有开发、审查和交付流程，不另设一套质量标准。

## 1. 每日约定时间确认

建议每天 17:30（Asia/Shanghai）在对应项目的现有任务中询问一次：“今晚有没有需要持续跟进的需求、功能、缺陷或测试？需要推进到什么结果？”具体时间和是否包含休息日由用户确定；未另行约定时“每天”包括休息日。

只从当前项目已有任务和记录中整理少量候选，附当前状态与阻碍；已有信息不重复询问。不要跨项目汇总，也不要因有未完成事项就自动选定任务。用户未回复或表示今晚不做时，不启动新的夜间执行，不连续催问；已获明确授权且仍有效的任务按原约定继续。

提醒需要实际调度能力。用户要求启用时，使用环境提供的 automation/scheduled-task 工具，先查重，优先复用当前任务的提醒；写清时区和执行范围并核对保存结果。只安装 skill 或写入本文不等于已经设置提醒。用户未要求新任务时不自动创建独立会话；不能用常驻 shell、忙等或循环发消息冒充调度。

## 2. 选定当晚目标

根据用户回复和已有上下文整理以下最小执行约定，不为已明确事项重复审批：

```text
任务与仓库：今晚处理哪一项，在哪个任务/工作区接续
目标与验收：要达到的可验证结果，完成后停止
范围与权限：可改哪些内容，是否已授权提交、推送、提测/创建 MR
当前版本：分支/提交、已有修改、相关 MR、环境与前置条件
时间与预算：用户指定的截止时间（含日期与时区）、交接时间或预算；未指定则不编造
停止条件：目标达成、用户要求停止、预算/时间限制或外部阻碍
```

“今晚继续做”若已明确指向一个任务，可作为该任务继续实施的授权；模糊的候选清单不能据此启动所有任务。目标是“分析需求”时只交付分析；目标是“执行测试”时不自动扩大到修复所有失败。禁止将“持续跟进”理解为合并、生产部署、扩大权限或修改真实业务数据的通用许可。

## 3. 启动 goal 并持续推进

- 只有用户明确要求 goal/持续目标模式并选定具体目标后，才调用环境提供的 goal 工具。写入具体目标和验收条件；仅当用户给出 token 预算时设置对应预算，不自行填默认值。
- 已有未完成 goal 时先查询并接续，不覆盖或重复创建。goal 的完成、暂停、受阻等状态按实际工具契约更新，不发明状态接口；预算或时间耗尽不能标成目标完成。
- 执行环境没有 goal 功能时如实说明，完成当前可以执行的部分并留下接续记录，不把普通对话或定时提醒称为 goal 已启动。
- 运行前确认工作区、任务分支、测试目标与必要凭证/环境可用。避免同一分支同时被白天工作和夜间任务修改；需要隔离时使用 worktree，保留原有未提交内容。
- 遵循 `development-workflow` 的需求澄清、缺口/复用分析和最小实现；已有有效计划和检查结果不重做。每个可验证步骤完成后记录版本、结果及下一步。
- 遇到失败先定位根因；同类重试没有新证据时停止该尝试，记录阻碍及解除条件，推进其他独立且已授权的部分，不靠无限重试耗尽夜间资源。
- 测试负责人的验收、用户业务决定或缺失外部权限不能自行补成“通过”。即使夜间无人回复，也保持相应交付关卡未完成；是否把 goal 标为受阻仍按工具契约执行。
- 到达用户指定截止时间时停止启动新工作，安全收尾并交接，不强杀可能写数据的操作。不为凑满整晚延长已完成任务，也不承诺本地机器休眠、断网或执行服务不可用时仍能持续运行。

## 4. 次日交接

完成或到达约定交接点后，在原任务和项目已有记录中给出以下内容，用户上班即可查看并继续：

```text
夜间目标：原定范围与当前结果
完成项：实际改变及对应提交/产物/MR；无提交时给出保留改动的位置
验证证据：版本、命令/场景、环境、结果；失败和未验证项明确列出
未完成项：阻碍、影响、已经尝试的办法及解除条件
当前状态：开发中/待验收/待合并/待发布等，goal 的实际状态
白天接续：需要用户或测试负责人确认什么，建议先做哪一步
```

交付前执行既有质量门禁。明确区分已实现、已验证、已提交、已合并和已上线，不以任务运行了一夜证明有效产出。结束时不清理仍含未交付工作的分支或 worktree。

夜间只在完成、实质进展、失败或需要用户操作时通知；每日一次的任务确认是用户主动要求的例外，不额外增加小时级状态消息。次日自动提醒的时间若未约定，只保留交接结果，不擅自另建早间定时任务。

## 调用示例

`今晚用 goal 模式继续订单退款修复，目标是回归测试通过并创建测试 MR，先不合并。明早在这个任务给我完成项、证据和阻碍。`

`每天北京时间 17:30 问我当晚需要持续跟进的任务；没回复就不要启动新目标。`

调度产品能力与运行条件参考 [Codex scheduled tasks 官方说明](https://learn.chatgpt.com/docs/automations?surface=app)；具体 goal 和调度操作以当前环境工具契约为准。
