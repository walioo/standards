# 代码知识图谱增强

知识图谱用于发现现有能力、模块关系、调用链和变更影响；不绑定业务、语言或图谱产品。项目已有可用图谱且任务涉及关系分析时优先使用，不要求文案修改等简单任务查询图谱，也不把安装图谱作为工作流前置门禁。

## 使用前核对

- 按实际仓库路径匹配索引，确认分支/worktree、索引版本及覆盖范围与本次对象一致；同名项目不代表同一工作区。多仓库只查询本任务涉及的项目。
- 索引显示 ready 只表示可查询，不证明对应当前 SHA 或包含未提交修改。工具未提供版本信息时明确新鲜度未确认，用当前源码和 Git diff 补核；过期结果只作定位线索。
- 需要刷新时沿用项目已有索引入口和数据权限，优先更新受影响范围；不擅自安装服务、上传代码到新平台或覆盖其他工作区索引。工具不可用时使用源码搜索、语言工具、Git diff 和测试继续执行，说明关系覆盖缺口。

## 在现有阶段使用

| 阶段 | 查询目的 | 留下的结果 |
|---|---|---|
| 现状与复用调查 | 从入口、符号及模块依赖查已有实现，沿调用/数据流核实责任归属 | 可复用位置、相关调用链与源码依据 |
| 方案与实现 | 从拟修改符号追踪调用方、被调用方及适用的跨服务契约 | 受影响入口、组件和需要验证的行为 |
| 审查与回归 | 按真实 base/head 和工作区变化分析影响，补查间接调用方和相关测试 | 实际 diff 与影响范围的对应、回归场景及缺口 |
| 交付与接续 | 记录仍有价值的依赖关系和证据来源；版本变化后重查受影响关系 | 简短的版本、影响范围、已验证与待验证事项 |

不另建重复报告或固定节点数量指标；结果放进已有方案、审查或交接记录。新增架构决策只有在项目已有维护约定或用户要求时才写入对应记录，不将本次推测自动沉淀为长期事实。

## 关联性审查与协作通知

开发前初查、最终 diff 审查时复核：本次功能是否影响其他服务、接口或消费者。所有代码变更先判断适用性；局部变更可简述结论，不要求全仓扫描。此项不依赖图谱安装，已有图谱用于定位，仍按前述版本和证据要求核实。

- 从变更入口及共享契约双向追踪调用方和被调用方，按实际影响覆盖 API/RPC、事件/消息、共享数据、配置及客户端/定时任务等消费者。不能只检查接口签名：字段语义、默认值、错误码、权限、单位、时序、副作用或负载变化也可能影响下游。
- 对受影响对象核对兼容性、需要的配套修改、联调场景及部署先后关系。只检查证据指向的服务和接口；无法读取消费者实现或确认使用版本时列为待确认，不以搜索无结果判为无影响。
- 结论区分“在已查范围未发现外部影响”“存在外部影响”“证据不足待确认”，附关键依据与未覆盖范围。发现影响或可信风险时立即在当前任务主动提醒开发者，不等到最终交付；说明已确认事实与待确认项。
- 需要其他服务知悉或配合时，在现有任务/PR 中整理可转发通知：本次变更与版本/PR、受影响服务及接口、兼容性与风险、对方需做的动作和联调验证、必要的发布时间/顺序。接收人和渠道取自项目维护关系，不猜测；不把代码中的服务名当成通知地址。
- 实际向其他团队/任务发送通知须有用户明确发送授权或已明确授权的通知流程，并确认接收对象与渠道。已有有效授权则执行，不重复询问；缺少授权或目标时保留完整通知草稿并说明待发送原因，不宣称已通知，不擅自扩大到修改其他服务。
- 区分“待发送”“已发送”“已确认”“配套修改/联调已完成”，已发送须有实际发送结果或链接；发送失败保留待办，结果不明先核对再重试。通知送达不等于对方已适配或验收通过。

破坏性变化或必须协同的配套工作未完成时，阻断依赖它的发布关卡，继续可独立执行的工作；兼容且无配套动作的知会不默认新增审批。影响范围或契约发生实质变化时更新结论及必要通知，无变化不重复催发。

## 证据边界

图谱命中后读取当前源码核实关键路径，不能把依赖边当作已发生的运行行为。未命中不等于不存在；反射、动态路由、依赖注入、生成代码和异步/跨服务关系可能缺失，应结合配置、契约、消费者代码及适用运行证据补查。跨仓库边只有在相关索引与版本均可核对时才能支持当前组合判断。

调用关系只能帮助选择回归测试，不能证明测试已执行或断言有效；自动风险标签也不能直接作为问题严重程度。放行仍以当前版本的源码、必需检查及验收证据为准。

## 已有 codebase-memory 工具的接入示例

使用当前环境实际暴露的工具契约；其他图谱产品可提供等价能力，无需实现这些同名接口。

- `list_projects` / `index_status`：匹配仓库和检查索引状态；状态未包含 SHA 时不能据此宣称最新。
- `get_architecture`：查看模块及依赖，作为调查起点。
- `search_graph` → `get_code_snippet`：先定位准确符号，再读取实现；同时核对当前工作区文件。
- `trace_path`：按需要追踪调用、数据流或跨服务路径，注明方向、深度与覆盖限制。
- `detect_changes`：显式按工具契约选择比较基线和变更范围，并与真实 Git diff 核对；不能默认它包含全部未提交或未跟踪文件。

索引建立/刷新与只读查询分开处理；不为接入规范自动重建全部服务图谱。
